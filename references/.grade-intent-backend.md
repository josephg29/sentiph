# Design intent — Sentiph backend (read before grading; treat as in-scope/by-design)

`apps/api` is the backend: a Node HTTP control-plane + WebSocket/PTY data-plane for running
Claude Code agents locally. Shared domain types live in `packages/core`. The following are
deliberate choices — do NOT score them down as defects.

- **Local-first, single-user tool, not a multi-tenant web service.** The server binds to
  `127.0.0.1` by default (`server.ts`) and only requires a pairing token when
  `SENTIPH_ALLOW_REMOTE_ACCESS=1`. Loopback requests are intentionally exempt from auth
  (`security.ts isAuthorizedRequest`). Judge auth/CORS in this threat model, not as a public API.
- **Ports-and-adapters in `packages/core`** (domain/* types, ports/* contracts, adapters/*
  implementations) with `apps/api` as the composition root. Factories take many injected
  function params on purpose — that is DI, not parameter bloat.
- **No traditional database by design.** State is JSON / JSONL under `~/.sentiph/...`
  (`projectPersistence.ts`, `conversationStore.ts`, `agentMetricsStore.ts`). Absence of SQL
  migrations/indexes is intentional for a single-user local tool. Documents are versioned
  (`version: 1`) and parsed defensively.
- **HTTP control-plane + WS/PTY data-plane split.** Terminal lifecycle is REST; live terminal
  I/O flows over WebSockets (`sessionRuntime.ts`).

## Calibration anchors (this project, current state — score RELATIVE to these)
- **API Design = 87.** RESTful plural-noun resources, prefix-dispatch router, correct methods +
  status codes (201/204/400/404/405/409/413/429). Deduction: no uniform `{success,data,error}`
  envelope, no `/api/v1` version prefix, list endpoints return bare arrays w/o pagination meta.
- **Error Handling = 90.** Centralized top-level try/catch returns generic 500 while logging full
  context; stack traces gated behind verbose logging; typed errors split validation (400/409/413)
  from server errors. Deduction: a couple of FS failures are logged-and-swallowed returning 200.
- **Data Model = 89.** Typed end-to-end, camelCase, explicit relationships, versioned+validated
  documents, zero `any` in prod. Deduction: hand-rolled validation (no Zod); conversationStore
  returns `unknown[]` instead of the typed core models.
- **Security = 86.** No hardcoded secrets; crypto-random in-memory pairing token verified with
  `timingSafeEqual`; Host/Origin allowlists; resolved-path traversal guard; git/gh via
  `execFileSync` arg-arrays (no shell); 1MB body cap. Deduction: WS upgrade path enforces only
  Host/Origin and does NOT token-gate the PTY channel in remote mode (auth inconsistency).
- **Code Organization = 91.** Thin route handlers → service layer → JSON persistence; HTTP
  plumbing/validation/security/rate-limit each in dedicated modules; largest file ~486 lines.
  Deduction: `handleTerminalsCollectionRoute` (~215 lines) leaks validation into the HTTP handler.
- **Performance = 89.** `fs/promises` on hot paths, mtime-windowed transcript reads, per-tentacle
  git cache w/ TTL + eager invalidation, background usage cache. `agentMetricsStore` now memoizes
  the parsed `summaries.jsonl` by mtime+size (shared across the aggregate/summaries/heatmap
  endpoints the Observe UI polls together), so the per-request re-parse is gone. Remaining
  deduction: `searchConversations` is still an un-indexed O(n) full-corpus scan, and the heatmap's
  per-event-file scan is uncached.
